## Summary
`vault.algolia.net` (in scope via `*.algolia.net`) exposes a production HashiCorp **Vault** HTTP API to the public
internet. Its unauthenticated system endpoints return `200`, disclosing that Vault is running **v1.16.2** (OSS,
build 2024-04-22) — an outdated release missing multiple later security fixes, including **CVE-2024-5798** (a JWT
audience/claim validation flaw fixed in the very next release, 1.16.3). A production secrets manager should not be
internet-reachable, and should be patched.

## Steps to Reproduce
```bash
curl -s https://vault.algolia.net/v1/sys/health
# -> 200 {"initialized":true,"sealed":false,...,"version":"1.16.2","enterprise":false,
#         "cluster_name":"vault-cluster-0d3c6369","cluster_id":"9075ba06-..."}

curl -s https://vault.algolia.net/v1/sys/seal-status
# -> 200 {"type":"shamir","initialized":true,"sealed":false,"t":2,"n":18,"version":"1.16.2",
#         "build_date":"2024-04-22T16:25:54Z","storage_type":"raft","cluster_name":"vault-cluster-0d3c6369",...}
```
Both endpoints respond `200` from an arbitrary internet host with no authentication, network ACL, or client
certificate, confirming the Vault API is publicly reachable.

## Impact
1. **A production secrets-management service is exposed to the public internet.** Although `/v1/sys/health` and
   `/v1/sys/seal-status` are unauthenticated by design, their reachability proves the full Vault API surface
   (including `/v1/auth/*` login endpoints) is not restricted to an internal network. This unnecessarily widens the
   attack surface of a critical component and enables unauthenticated CVE matching and targeted attacks.
2. **Outdated version (1.16.2).** The exact version is disclosed and is missing later security fixes:
   - CVE-2024-5798 (fixed 1.16.3) — JWT `aud`/bound-claim validation could let an invalid login succeed.
   - CVE-2024-6468 (fixed 1.16.6) — denial of service on the TCP listener.
   - Additional fixes through the later 1.16.x line are absent.
3. Discloses `cluster_id`, `cluster_name`, unseal quorum (`t:2, n:18`), storage backend (`raft`), and build date.

## What was NOT done
No authentication attempts, no exploitation of CVE-2024-5798 or any auth endpoint, no writes — testing was limited
to the two read-only, unauthenticated monitoring endpoints. This report demonstrates *exposure + outdated version*,
not a Vault compromise.

## Remediation
- Restrict `vault.algolia.net` to internal networks / VPN / IP-allowlist, or require mTLS at the edge; do not serve
  the Vault API to the public internet.
- Upgrade Vault to a current patched release (≥ 1.16.22 in the 1.16 line, or a newer supported line).
- If JWT/OIDC auth methods are configured, prioritize the CVE-2024-5798 fix.
